Review a browser journey for each criterion

Write one action per line. Quote visible labels and text. Every criterion needs at least one expect assertion. Review that the assertions actually establish its expected outcome.

Supported actions and example
open /
fill "Item name" "Example item"
click button "Add item"
expect text "Example item"

Use click button "Name" or click link "Name" for accessible controls. expect heading "Name" checks a visible element. Supported roles: button, link, heading, textbox, checkbox, radio, tab, status.

For elements with a test ID, use click testid "add", expect testid "result", or expect testid "result" "Exact text". fill "Field label" "Value" uses a field’s label. Text and names match exactly.

This first check runner covers local browser navigation, clicks, form entry, visibility, and text. It cannot verify uploads, downloads, external APIs, performance, or arbitrary scripts. Keep unsupported requirements explicitly outstanding; do not replace them with an unrelated text assertion.
